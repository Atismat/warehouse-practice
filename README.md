# Warehouse practice — склад ответственного хранения

Учебный прототип учёта целых коробок: приёмка, best fit, FIFO, резервирование заказа целиком, выдача и отмена. Учебные клиенты C1/C2; реальных клиентских данных нет.

## Среда

Python 3.10+ со стандартной библиотекой; SQLite 3.37+ внутри `sqlite3`; JDK 21 (`java`, `javac` в PATH). Сторонние Python/Java-библиотеки не нужны. Проверенная среда — `docs/protocols/environment.txt`.

## Запуск из корня проекта

```sh
python3 src/demo.py
python3 src/scenario.py data/demo.tsv
mkdir -p build
javac -Xlint:all -d build java/src/warehouse/*.java
java -cp build warehouse.Runner data/demo.tsv
python3 -m unittest discover -s tests -v
```

Windows PowerShell: вместо `mkdir -p build` используйте `New-Item -ItemType Directory -Force build`; вместо glob передайте два исходника `java/src/warehouse/Warehouse.java java/src/warehouse/Runner.java`. Вместо `python3` допустимо `py -3`.

Контроль: L1→A02, L2→A01, L3→A02. Заказ O1 клиента C1 на P1:60 получает L1:40 и L2:20; доступно C1 30. После выдачи L1/L2/L3 = 0/30/10; загрузка A01/A02 = 30/10; статус SHIPPED; журнал содержит пять движений. В тестах — 40 проверок, в том числе полное сравнение 92 состояний Python/Java в 15 общих сценариях. Сравниваются значения, планы, резервы, статусы, последовательность и журнал.

## База данных

```sh
python3 src/storage.py warehouse.sqlite
```

Команда создаёт НОВЫЙ файл и загружает результат `data/demo.tsv`. При существующем файле отказывает, чтобы не затереть данные. Для повторной демонстрации укажите другое имя. Из Python: `connect(path)`, `create(db)`, `save(db,state)`, `load(db)` в модуле `storage`. **`save` заменяет весь снимок в одной транзакции**; при отказе сохраняет предыдущий снимок. Не используйте его с производственными БД.

DDL: `sql/schema.sql`; диагностические запросы: `sql/checks.sql`; фактический вывод: `docs/protocols/sql_checks.txt`. Выполнить запросы можно через стандартный модуль Python:

```sh
python3 -c "import sqlite3,pathlib; db=sqlite3.connect('warehouse.sqlite'); [print(s.strip(),db.execute(s).fetchall()) for s in pathlib.Path('sql/checks.sql').read_text().split(';') if s.strip()]"
```

Восемь таблиц соответствуют логической модели. `used` и `reserved` вычисляются представлениями `cell_balance`, `lot_balance`. Составные внешние ключи проверяют владельца и товар резерва. Ограничения и триггеры защищают типы, знаки, статусы и вместимость. Полное соответствие журнала и остатков, покрытие строк заказов, состояние резервов проверяются модулем сохранения и диагностическими запросами, а не всеми возможными произвольными SQL-изменениями. Редактирование БД в обход модуля не является поддерживаемым рабочим процессом.

Python сохраняет/загружает снимок через SQLite. Java работает в памяти и читает TSV; прямого JDBC-подключения нет. Формат обмена и сравнения — JSON Lines, даты нормализованы в UTC.

## Структура

- `src/` — процедурная логика, демонстрация, TSV-протокол, SQLite;
- `java/src/warehouse/` — объектная модель, интерфейсы стратегий, запуск;
- `data/demo.tsv`, `data/scenarios.tsv` — общие исходные операции;
- `sql/` — схема и проверки;
- `tests/` — исходные и расширенные автоматизированные проверки;
- `docs/diagrams/` — новые UML/физическая модель в SVG, PNG и редактируемом drawio;
- `docs/protocols/` — исходный и итоговый запуск, тесты, среда, SQL;
- `docs/test_scenarios.md` — входы, ожидаемые и фактические результаты;
- `docs/design.md` — решения, ограничения, отладка, команда;
- `docs/language.md` — аннотации, заключения, глоссарий, выступление.

Ранее созданные PNG-схемы сохранены в `docs/`; их редактируемые исходники в исходном комплекте отсутствовали. Они отражают ранние этапы. Файлы `data/demo_result.txt` и `docs/test_results.txt` — исходные контрольные протоколы; актуальные результаты расположены в `docs/protocols/`.

## Формат TSV

UTF-8, табуляция; пустые строки и строки `#` пропускаются. Операции:

```text
RESET
RECEIVE<TAB>lot<TAB>client<TAB>product<TAB>quantity<TAB>timestamp
RESERVE<TAB>order<TAB>client<TAB>P1:60,P2:1
SHIP<TAB>order
CANCEL<TAB>order
BLOCK<TAB>lot<TAB>1
AVAILABLE<TAB>client<TAB>product
```

Даты общего протокола: `YYYY-MM-DDTHH:MM:SSZ` или с числовым смещением `±HH:MM`, без дробных секунд. Клиенты C1/C2, товары P1/P2, ячейки A01:100 и A02:60 заданы демонстрацией. Количества общего интерфейса — десятичные целые в диапазоне Java `int`; фактически размещаемое количество ограничено вместимостью. В строке заказа товар указывается один раз. Java-поля скрыты; состояние меняется через сервисные методы. `ERROR` означает ожидаемый отказ без изменения состояния. Ошибки структуры TSV вне описанного формата не маскируются.

## Ограничения

Один склад, одинаковые коробки, одна ячейка на партию; FIFO, не FEFO. Нет GUI, API, температурных режимов, расчёта услуг, прав доступа, параллельных операций и интеграции с WMS. Атомарность предметных отказов в памяти не означает устойчивость к аварийному завершению процесса. Сохранение SQLite — транзакционный снимок, не сервер многопользовательского учёта. Производительность и экономический эффект не измерялись. Python `check_invariants` — диагностика на `assert`; запускайте проверки без `-O`.

Лицензия автоматически не назначена. История исходного Git-репозитория сохранена в переданном архиве проекта; веб-публикация содержит проверенные исходники и материалы.
