Тема: складская логистика и ответственное хранение. Этапы 2 и 3.

## Запуск

Требуется Python 3.10 или новее. Внешних библиотек нет. Проверено на Python 3.12.14.
Откройте терминал в папке warehouse_practice:

```sh
python3 src/demo.py
python3 -m unittest discover -s tests -v
```

В Windows вместо `python3` можно использовать `py`.

Ожидаемый результат: FIFO-план `[('L1', 40), ('L2', 20)]`, доступно клиенту C1 30 коробок;
после выдачи остатки L1/L2/L3 равны 0/30/10. Заказ SHIPPED. Проверки: 19 тестов, OK.
Полные сохранённые результаты: `data/demo_result.txt` и `docs/test_results.txt`.

## Что реализовано

- Подбор одной ячейки минимальной достаточной вместимости (best fit).
- Приёмка партии и журнал движений.
- FIFO по времени приёмки, затем по последовательному номеру.
- Изоляция владельцев и исключение заблокированных партий.
- Резервирование всех строк заказа целиком или отказ без изменений.
- Выдача и отмена; запрет повторного списания.
- Контроль остатков, резервов и вместимости.

Предметная логика процедурная: функции, словари, списки. Классы используются только
в тестовом наборе unittest. Все данные условные; деятельность БФТ не моделируется.

## Ограничения

Один склад, одинаковые по объёму коробки, целые количества, партия в одной ячейке.
Без срока годности и без температурных режимов. Не применяется к опасным грузам.
Данные хранятся в памяти; при новом запуске демонстрация создаёт их заново.
Нет параллельных операций, БД, интерфейса, расчёта услуг или интеграций.
Атомарность проверенных отказов обеспечивается внутри одного процесса;
аварийное завершение и многопользовательские транзакции не обрабатываются.
`check_invariants` — диагностическая проверка: запускайте без флага Python `-O`.
